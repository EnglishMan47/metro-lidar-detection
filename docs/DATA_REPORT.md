## Выводы для архитектуры

1. Нельзя жёстко задавать `/lidar_points`: положительный bag использует другое имя topic. Нужно искать `PointCloud2` и позволять явное переопределение параметром.
2. Положительный bag втрое плотнее и имеет другой frame. Детектор не должен считать размер сообщения признаком препятствия; облако следует нормализовать и проверять независимо от количества точек.
3. Архив не содержит отдельного файла разметки. Имя каталога указывает на сценарий, но границы препятствия, время появления и эталонное расстояние необходимо определить при визуальном разборе.
4. Пять отрицательных/штатных проездов охватывают платформу, стрелку, гермозатвор и несколько типов тоннеля. Их нужно использовать для оценки ложных тревог, разделяя метрики по сценарию.
5. Один положительный проезд не позволяет честно оценить обобщаемость. Синтетические тесты и скрытый контроль организаторов критичны, а результаты на синтетике следует показывать отдельно.

## Первичное декодирование облаков

Скрипт `scripts/inspect_pointcloud_bag.py` напрямую декодировал CDR-представление `PointCloud2` из SQLite3 без ROS. Проверены начало, середина и конец каждого bag — всего 18 кадров. Полный отчёт: `artifacts/pointcloud_inspection.json`.

- Схема полей и размеры сообщения согласованы во всех 18 кадрах; декодер поддержал оба topic/frame.
- В выборках много конечных заполнителей `(0,0,0)`: примерно 38–62% просмотренных точек в зависимости от кадра. Их нужно удалять до расчёта статистик и детекции.
- По форме тоннеля и диапазонам координат предварительно установлено: продольное направление вперёд соответствует `-Y`, поперечная координата — `X`, высота — `Z`. Это вывод из данных, который ещё нужно подтвердить в ROS/RViz и конфигурации сенсора.
- Для ненулевых точек 99-й процентиль дальности по просмотренным кадрам составляет примерно 47–82 м, однако единичные возвраты достигают 200–209 м. Дальность 100+ м нельзя оценивать только по общему максимуму: нужны устойчивость к разреженности и отдельный отчёт по числу возвратов.
- Диагностические проекции положительного bag и чистого перехода сохранены в `artifacts/*.png`. Они подтверждают геометрию тоннеля, но не заменяют ручную привязку двух препятствий по кадрам.
